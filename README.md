# Agent Monitor

PCで開いているCodexとClaude Codeの会話を、スマホから読むための個人用ツールです。
プロジェクト別の一覧から会話を選び、過去の出力を読み、次の指示を送れます。
PC側のCLIが処理するため、スマホを閉じても作業は続きます。

## 起動

初回セットアップにはNode.js 24以上とpnpm 10を使います。
リポジトリのディレクトリで、次の順に実行します。

1. `pnpm install`で依存を用意します。
2. `pnpm build`で画面をビルドします。
3. `mkdir -p ~/.local/bin`でコマンドの配置先を作ります。
4. `ln -s "$PWD/bin/agent-monitor" ~/.local/bin/agent-monitor`でシンボリックリンクを作ります。

`~/.local/bin`をPATHに含めて使います。
PATHにNode.js 24以上がなければ、macOSではHomebrewの`node@24`を使います。
必要なら`brew install node@24`で用意してください。

PCでCodexまたはClaude CodeをHerdr内に起動します。
続いてHerdrのターミナルで実行します。
インストール後は任意のディレクトリから起動できます。

```sh
agent-monitor
```

終了するには、起動したターミナルでCtrl+Cを押します。
ポートやsocketを明示する場合は、次のように指定します。

```sh
agent-monitor --port 4320 --codex-socket /absolute/path/app-server-control.sock --herdr-socket /absolute/path/herdr.sock
```

Codexのsocketは、CLI指定、`CODEX_APP_SERVER_CONTROL_SOCKET`、`CODEX_APP_SERVER_CONTROL_SOCKET_PATH`の順で選びます。
指定がなければ`CODEX_HOME/app-server-control/app-server-control.sock`を使います。
`CODEX_HOME`もなければ`~/.codex`を基準にします。
Herdrは`--herdr-socket`または`HERDR_SOCKET_PATH`で指定します。
Herdrで現在開いているCodex TUIとClaude Codeの会話を表示します。
Herdrを利用できない場合は接続エラーを表示します。
macOSの`lsof`でforeground PIDのLISTENとwriter lockのFDを読み、会話IDとの対応を確認します。
shared daemonでは、会話の`codex_tui`接続のloopback originとLISTEN portが一致することを確認します。
embedded CLIでは、現在のPIDが保持するwriter lockから会話IDを確認します。
対応を確定できない端末は除外し、件数を接続表示へ出します。
監視接続の購読は、ロード済み一覧の取得後に解除します。
購読解除に対応したCodexが必要です。
CLI終了後は、daemonに会話が残っていても一覧から外れます。

Claude Codeは、PCのPATHから`claude agents --json`を実行できる状態で使います。
interactiveセッションのPIDとcwdがHerdrのforegroundプロセスと一意に一致し、sessionIdを確認できる会話を表示します。
一覧の種類表示と会話の発言者名で、CodexとClaude Codeを区別できます。
Claude Codeだけを開いている場合は、Codexのsocketへの接続は不要です。
Codexも開いている場合、Codexのsocketに接続できなければ接続エラーを表示します。
セッション一覧の形式は[Claude Codeの公式仕様](https://code.claude.com/docs/en/agent-view#list-sessions-as-json)に基づきます。

## スマホとQRコード

初回はPCのTailscale.appで接続を有効にし、HTTPSとServeを設定します。

```sh
tailscale serve --bg --https=443 http://127.0.0.1:4317
```

このPCでは`tailscale`がPATHにない場合、次の実行ファイルを使います。

```sh
/Applications/Tailscale.app/Contents/MacOS/Tailscale serve --bg --https=443 http://127.0.0.1:4317
```

HTTPSを初めて有効にするときは、コマンドが表示するURLをブラウザで開いて利用を許可します。
許可後、必要なら同じコマンドを再実行します。
`--bg`の設定は保存され、Serveコマンドを閉じた後やPCの再起動後も使えます。

1. スマホのTailscaleに、PCと同じアカウントでログインします。
2. Herdrのターミナルで`agent-monitor --tailscale`を実行します。
3. PCの起動出力にあるQRコードをスマホで読み取ります。

URLとQRコードは`https://PC名.tailnet名.ts.net`形式の固定HTTPS接続先です。
TailscaleのDNS名を変えなければ、Agent Monitorを再起動しても同じURLを使えます。
認証トークンの保存は不要で、ブックマークやホーム画面から接続できます。

tailnetのアクセスルールで、このPCのTCP 443への接続を許可する必要があります。
API操作は、Serveが確認した`Tailscale-User-Login`とPC所有者の`LoginName`が完全一致する場合に限り許可します。
Tailscale Serveが受信した識別ヘッダーを検証済みの値で置き換えます。
Funnelは無効にし、同じHTTPS接続先のルートはAgent Monitor専用にします。

両モードとも、アプリは`127.0.0.1`だけで接続を受け付けます。
PC内のプロセスは信頼する前提です。
ポートは指定がなければ4317です。
`--port 4320`に変える場合は、Serveの転送先も`http://127.0.0.1:4320`へ変更します。
Tailscale停止中、永続HTTPS設定がない場合、転送先が異なる場合は起動を中止し、設定手順を表示します。
Ctrl+CでAgent Monitorを終了すると、再び起動するまで接続できません。

PC内で使う通常の`agent-monitor`は、ローカルHTTPと起動ごとの認証トークンを使います。
このモードのURLにある認証情報はsessionStorageへ移し、アドレス欄から消します。
QRコードと起動出力は、PCを操作できる認証情報として扱ってください。
再起動後やトークンを失った場合は、その起動時のURLまたはQRコードから接続します。

## 作業完了と質問の通知

`agent-monitor --tailscale`で起動すると、一覧に通知の操作を表示します。
iPhoneではSafariの共有メニューからホーム画面に追加し、追加したアプリを開きます。

1. 一覧の「通知を有効にする」を押し、端末の通知を許可します。
2. 「通知は有効です。」と表示されたら、「テスト送信」で受信を確認します。
3. 解除するときは、同じ端末で「通知を解除する」を押します。

PCで作業中から待機へ変わった会話と、新しい未回答のCodexの質問を約5秒ごとに確認します。
起動時にすでにある完了や質問は、通知の基準に含めます。
新しく現れた質問は、会話をスマホで開いていなくても通知します。
Claude Codeは作業完了を通知します。
通知を押すと、固定HTTPS接続先で対象の会話を開きます。
会話が終了している場合は、一覧に案内を表示します。
質問への回答は、既存の会話画面で行います。

アプリを閉じていても、PCとAgent Monitorが起動し、インターネットに接続していれば通知を送信できます。
通知から会話を開くには、スマホのTailscale接続が必要です。
通知には会話名と完了・質問待ちの区別を載せます。
会話本文と質問の内容は通知へ含めません。
実際の到着時刻は端末と配信サービスによって変わります。

VAPID鍵と端末の購読情報は、PCの`~/.local/share/agent-monitor/notifications.json`にまとめて保存します。
ディレクトリは0700、ファイルは0600で作成し、再起動後も同じ登録を使います。
保存ファイルを読み書きできない場合は、ファイルを保全して通知だけを無効にし、一覧にエラーを表示します。
PCで保存先を確認してからAgent Monitorを起動し直してください。
ローカルHTTPモードには、HTTPSでの起動案内を表示します。

## 会話を読む・送る

1. プロジェクト・会話名の検索で会話を探します。Codexは冒頭の指示でも検索できます。
2. 会話を開き、必要なら「前の履歴を読む」で過去を追加します。
3. 「次の指示」に入力し、「指示を送信」を押します。

Enterは改行です。
送信はボタンで実行します。
ピン留めはブラウザのlocalStorage、下書きは会話ごとにsessionStorageへ保存します。
上の履歴を読んでいる間は位置を保ち、新しい出力は「新着へ」で表示します。
連続したツール実行は、件数と状態をまとめて表示します。
詳細を開くと、個々のコマンドと出力を確認できます。
内部Agentの会話とreasoning、thinking項目は会話本文から除外します。
送信直前にCLIとHerdrの最新状態を確認します。
Codexで待機中や作業が完了した会話に、共通queueを通して指示を渡します。
daemonにロードされないembedded CLIも、このqueueから指示を取り込みます。
取り込みには約10秒かかることがあります。
確認後にPC側で作業が始まった場合、送信した指示は次の指示として待機します。
待機中の指示は入力欄の上に表示します。
処理中は、同じ入力欄からPCのCodexやClaude Codeへ追加の指示を送れます。
対応する会話・前面プロセスと、PCの入力欄が空であることを確認し、文字とEnterを送ります。
複数行も1つのメッセージとして送信します。
PCに下書きがある場合、入力欄を認識できない場合、対象が変わった場合は送信を拒否し、スマホの下書きを保持します。
CLIコマンドは端末画面から入力してください。
承認待ち・質問待ち・状態未確認では送信ボタンを無効にし、下書きを保持します。
Herdrで待ち状態を検出した場合は「承認・回答待ち」と表示します。
daemonにロードされたCodex会話では、非同期の質問を通常の入力欄の上に自動で表示します。
選択肢を押すと回答欄に入り、編集してから「回答を送信」で送れます。
質問ごとの回答下書きは会話を切り替えても保持し、通常の指示の下書きとは別に保存します。
回答は現在のturnへ直接渡すため、PCの入力欄を保ちます。
回答済みや終了したturnの質問も、会話履歴から読めます。
回答結果が不明な場合は再送を停止します。PCで結果を確認し、「PCで回答結果を確認して解除」を押すと新しい操作として送信できます。
入力欄の「端末を開く」から、承認や処理を止めて待つ質問への回答を操作できます。
送信成功は指示の受付を示します。
作業の完了は、会話の状態と出力から確認してください。
最初の発言前も、同じ会話へ指示を送れます。
Claude Codeは待機中も端末への貼付けとEnterで送信し、PCの複数行下書きを保護します。
Claude Codeの履歴は`CLAUDE_CONFIG_DIR`または`~/.claude`の`projects/*/<UUID>.jsonl`から読みます。
userとassistantの本文とツール実行を表示し、system、meta、sidechainを除外します。
書込み途中の末尾は次回の更新で読みます。
履歴ファイルは64MiB、1行は2MiBまでです。
上限超過、解析失敗、ファイルの重複は履歴エラーとして表示します。
履歴だけを取得できない場合はエラーを表示し、状態とqueueを確認できれば送信できます。
一覧から消えた会話は端末の関連付けを解除し、履歴と下書きを保持したまま送信を無効にします。
PCで同じ会話を再開すると、通常の更新で再び操作できます。

操作ごとのIDで重複送信を防ぎます。
応答が切れて結果が不明になっても、自動で再送しません。
PCで結果を確認した後、解除ボタンで新しい操作を可能にします。
サーバー再起動で操作記録も消えるため、再接続後に同じ下書きを送る前にPCで確認してください。

## スマホから新しいCodex会話を起動する

PCのPATHから`codex`を起動できる状態で使います。

1. 一覧の「新しいCodex会話」を開きます。
2. `~/git/agent-monitor`など、PCの作業ディレクトリを入力します。
3. 「Codexを起動」を押します。
4. 信頼確認などの操作が必要なら「起動した端末を開く」から端末を表示し、キーを送ります。
5. 起動が完了すると会話を自動で開くので、「次の指示」から最初の指示を送ります。

絶対パスと、PCのホームを表す`~`・`~/`を使えます。
PCに存在するディレクトリを確認し、同じ場所のworkspaceに新しいタブを開きます。
該当するworkspaceがなければ作成します。
PCで操作中のフォーカスは維持します。

起動待ちの状態は「起動状態を確認」から開き直せます。
再読込や通信切断の後も、保存した起動IDで同じ要求の結果を取得します。
端末画面を閉じると起動状態へ戻ります。
どちらの画面を閉じてもPCのCLIは動き続けます。
起動中に操作できる対象は、今回作成した端末です。
起動が完了した後は、通常の会話画面の端末操作へ移ります。

起動結果が不明な場合は、新しい起動を停止します。
PCで作成済みのタブやCodexを確認してから、「PCで起動結果を確認して解除」を押してください。
確認前は、別の起動IDでもサーバーが追加の起動を拒否します。
確認しても元の起動を再実行せず、作成した資源も自動削除しません。
サーバーの再起動で記録が消えた場合も、PCで確認してから解除してください。

## 端末を操作する

1. 会話の「端末」を開き、タイトル・場所・pane IDから対象を選びます。
2. 「この端末を表示」で、最新の画面と対象名を確認します。
3. 文字またはキーを送信します。

現在のPID資源と選択した会話の対応を確認できた端末だけを候補で示します。
Codexは現在のOS資源で対応を判断し、Claude Codeは現在のセッション一覧と対応を確認します。
端末を閉じる、会話を切り替える、一覧に戻る操作で選択を解除します。
候補を変えた場合も選択を解除するため、「この端末を表示」で対象を確認し直してください。
関連付けの有効期間は30分です。

文字とEnterは別々に送ります。
文字欄では改行や制御文字を拒否します。
キーはEnter・Escape・Tab・矢印・Backspace・Ctrl-Cに限定します。
Ctrl-Cには追加の確認があります。
操作直前に端末ID・プロセス・会話ID・表示を再確認し、変わっていれば拒否します。
表示を更新した後、改めて確認してください。
端末の表示は操作後と更新ボタンで取得します。
最初は表示の末尾へ移動し、現在のpromptを表示します。
同じ端末の更新では、末尾を表示中なら追従し、過去を読んでいれば位置を保ちます。

## 制約

- Herdrで開き、現在のforeground PIDと対応を確認できたCodex TUIとClaude Codeが対象です。
- Codexの新規会話は一覧の「新しいCodex会話」から起動できます。Claude CodeはPCで起動します。CodexのresumeはPCでCLIを終了して起動し直します。同じCodex CLI内の`/new`や`/resume`による会話切替は対象外です。
- 1つの端末にuser会話の候補が複数ある場合は、誤送信を避けるため除外します。
- 更新は約2秒ごとの取得です。接続エラー時も取得済みの履歴を保持します。
- 操作記録と起動記録はサーバー起動中に保持します。上限は操作1万件、起動1000件です。上限に達したら再起動します。
- Markdownの画像と任意のHTMLは表示を制限します。リンクはHTTP・HTTPS・mailto・ページ内参照を許可します。
- スマホとの通信はTailscale ServeのHTTPSを使い、PC内の転送と通常起動はloopbackのHTTPを使います。

Herdrによる入力の直前確認と実際の入力は別のAPIです。
その間にPCで対象を変える競合は残るため、端末操作中はPC側で対象を切り替えないでください。

## 開発用の検証

```sh
pnpm install
pnpm build
pnpm check
pnpm test
pnpm test:browser
pnpm lint:text
```

テストは実際のHTTPと、fakeのCodex WebSocket・Herdr Unix socketを通します。
Claude Codeのセッション一覧形式と、実ファイルに追記したJSONL履歴も確認します。
`pnpm test`はDOMでの画面操作も確認します。
`pnpm test:browser`はGoogle Chromeで表示位置とスマホ幅の画面を確認します。
別の配置では`CHROME_PATH`で実行ファイルを指定してください。
画面の画像は`artifacts/`に出力します。

`pnpm lint:text`は、共通のtextlint設定とグローバル環境の`@babel/parser`を使います。
READMEと最終ファイル内の文言を検査し、抽出元と結果を`artifacts/textlint-report.json`へ保存します。
